# Syzygy tablebases

Task 035 adds optional endgame tablebase probing. The default build and the
default engine settings do not read tablebase files; probing starts only after
`SyzygyPath` (or `[uci] syzygy_path`) names a directory containing Syzygy
files.

## Setup

Use a directory containing the `.rtbw` (WDL) and `.rtbz` (DTZ) files directly:

```text
c:\games\see\Syzygy345\KQvK.rtbw
c:\games\see\Syzygy345\KQvK.rtbz
...
```

The engine was tested with the complete 3-4-5-piece set (145 `.rtbw` + 145
`.rtbz` files). Fathom also accepts a separator-separated list of directories
(`;` on Windows, `:` on POSIX). No tablebase data is included in the source
tree, runtime ZIP or installer.

UCI:

```text
setoption name SyzygyPath value c:\games\see\Syzygy345
isready
```

Or startup configuration:

```ini
[uci]
syzygy_path=c:\games\see\Syzygy345
```

Relative `[uci] syzygy_path` values are resolved against the configuration
file's directory (each list component for a separator-separated list). A later
UCI `setoption name SyzygyPath value ...` is relative
to the process working directory. `value <empty>` disables probing.

On load the engine reports one of:

```text
info string Syzygy loaded: 5-piece tables
info string Syzygy load failed: no Syzygy tablebase files found in ...
```

A failed load leaves the engine fully usable and falls back to search.

## Probing behavior

- At the search root, the engine uses Fathom's WDL+DTZ root probe. The
  position's halfmove clock and the fifty-move rule are applied. A root result
  is emitted as a normal `info depth 0` line with a
  `pv` move, preceded by a diagnostic such as
  `info string Syzygy WDL win DTZ 13`, and then `bestmove`.
- Root tablebase scores use the engine's search convention: a tablebase win is
  `95000` cp, a loss `-95000`, a cursed win `+1`, a blessed loss `-1`, and a
  draw `0`. These values stay below the mate band, so no false mate distance is
  reported.
- Interior search nodes use raw WDL probing only when the halfmove clock is
  zero. WDL tables do not encode distance-to-zero, so this conservative gate
  prevents a position that is only a fifty-move draw from being scored as a
  win. Nonzero clocks are handled by the root DTZ probe.
- Positions with castling rights are not probed. Syzygy tables do not cover
  castling positions, and the engine falls back to search.
- Positions with more pieces than the loaded set, or whose material file is
  missing, are not probed and fall back to search. A missing `.rtbz` file for a
  present WDL table also makes the root probe fall back rather than guessing
  fifty-move outcomes. En passant is passed through to Fathom.
- The root probe is a single-threaded operation. The SMP proof-of-concept
  helper workers do not use tablebases; the production build is
  single-threaded.
- Root tablebase results are emitted with `depth 0`, so the task-058
  resignation gate (which requires a completed search iteration) does not resign
  on a tablebase loss. The engine plays out the best tablebase move.

## Verification

With a local set:

```sh
TRY4_SYZYGY_PATH=/path/to/Syzygy345 ctest --test-dir build/performance \
  -R try4_syzygy --output-on-failure
```

The test suite checks a missing directory, a KQvK win, a fifty-move-sensitive
root, the piece-count limit, the search integration and the UCI option flow.
The tests skip automatically when no tablebase path is available.

For additional development verification against an independent prober:

```sh
python -m pip install python-chess
python scripts/syzygy_crosscheck.py --engine build/performance/try4_uci.exe \
  --syzygy c:\games\see\Syzygy345 --positions 200 --deep-check 60 \
  --output build/syzygy-crosscheck.json
```

The generator produces random KQvK/KRvK/KPvK positions, compares the engine's
root WDL with python-chess, validates the returned move, and optionally checks
the WDL sign against a depth-8 search on decisive KQvK/KRvK positions.
