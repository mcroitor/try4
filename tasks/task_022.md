## Objective

Create a deterministic single-threaded search that returns legal best moves
and principal variations, using a temporary material-only evaluator until
task 026.

## Context

This is the first search layer. It must handle mate scores, draw scores,
depth/node limits, and a stop flag. Quiescence, move ordering, the
transposition table, and clock-based time management arrive in tasks
023–024.

## Scope

### In scope

- Define search limits, results, info, and mate-score conventions.
- Implement negamax alpha-beta with fail-soft scores.
- Add iterative deepening and PV extraction.
- Integrate legal moves, results, and draw scores.
- Add tests for mates and deterministic fixed-depth behavior.

### Out of scope

- Quiescence search; task 023.
- Move ordering; task 023.
- Transposition table and clock-based time management; task 024.
- Evaluation beyond a documented material-only baseline; task 026.

## Requirements

1. `SearchLimits` supports depth and node limits (clock fields may be declared but are handled in task 024).
2. `SearchInfo` reports depth, score, nodes, and PV.
3. Use a clear mate-score convention, e.g. `MATE - ply`, with matching conversion for UCI later.
4. Negamax returns scores from the side-to-move perspective and uses alpha-beta bounds correctly.
5. Iterative deepening retains the best move/PV from completed depths and never returns an illegal move.
6. Return a legal best move; if no legal moves exist, return a null move or a documented no-move result.
7. Integrate `Position::Result()` and draw scores for terminal positions.
8. Use a temporary material-only evaluator, clearly marked for replacement by task 026.
9. Register the new tests under the `search` CTest label.
10. Add tests: mate-in-1, a position with a forced capture, no-legal-move handling, and deterministic same-depth best move.

## Deliverables

- Search API and implementation
- Temporary material evaluator
- Search unit tests
- Updated CMake target sources

## Acceptance criteria

- [ ] Search finds mate-in-1 in the test position.
- [ ] Search never returns an illegal move.
- [ ] Repeated fixed-depth searches on the same position are deterministic.
- [ ] No-legal-move positions are handled without crashing.
- [ ] PV moves are legal and consistent with the reported line.

## Validation

```sh
cmake --build build/cmake --config Debug
ctest --test-dir build/cmake -C Debug -L search --output-on-failure
```

Expected: search contract and mate tests pass.

## Constraints and failure modes

- Do not add a transposition table in this task.
- Do not add time-based nondeterminism to correctness tests.
- Do not return a move that was not generated by `LegalMoves()`.

## Completion notes

- Added `chess/search.hpp` and `chess/search.cpp` with fail-soft negamax,
  iterative deepening, triangular-free PV extraction, node/stop limits, and a
  documented `kMateScore - ply` convention.
- `SearchLimits` exposes depth, node limits (plus a compatibility alias), and
  the clock fields reserved for task 024. `SearchInfo` reports the completed
  depth, score, node count, PV, and optional best move.
- Terminal handling uses `Position::Result()`: checkmate is `-kMateScore + ply`,
  stalemates and draws are zero, and drawn roots with legal moves still expose a
  legal fallback move.
- Added the temporary material evaluator in `chess/evaluation.hpp` and
  `src/core/evaluation.cpp`, explicitly marked for replacement in task 026.
- Added seven tests: mate-in-one, checkmate/stalemate roots, winning capture,
  deterministic fixed-depth repetition, PV replay, node/stop fallbacks, and a
  drawn root. All 14 CTest executables pass.
